# 🏥 Clinic Doctor Analytics

Микросервис для визуализации аналитики врачей (выручка и перенаправляемость пациентов) на основе дампа PostgreSQL базы данных Cliniciq2.

## 📋 Требования

Для запуска проекта вам понадобятся:
- **Docker Desktop** (для Windows/macOS) или **Docker Engine + Docker Compose** (для Linux).
- **Git** (для клонирования репозитория).
- Файл дампа базы данных (`dump/demo_server_20260507.dump `).

> ⚠️ **Важно:** Файл дампа базы данных не включен в репозиторий из-за ограничений размера файлов на GitHub (>100 МБ).
> Пожалуйста, получите файл `dump/demo_server_20260507.dump ` отдельно от разработчика и положите его в папку `dump/` перед запуском.

### 1. Подготовка

Склонируйте репозиторий и перейдите в папку проекта:

```bash
git clone https://github.com/SenderovMaxim/clinic-analytics.git
cd clinic-analytics
```

Убедитесь, что файл дампа лежит по пути: dump/cliniciq2_db.dump.

### 2. Запуск сервисов
Выберите команду, соответствующую вашей операционной системе:
- 💻 Для Windows (PowerShell / CMD)
Если у вас установлен make (например, через Git Bash или Chocolatey):
```make up```. 
  Если make не установлен, используйте стандартную команду Docker Compose:
```docker compose up -d --build```
- 🐧 Для Linux / macOS
```make up```. 
Или, если вы предпочитаете прямые команды:
```docker compose up -d --build```

### 3. Доступ к приложению

После запуска (это может занять 1–2 минуты для восстановления базы данных) откройте в браузере:

- **📊 Аналитика врачей:** [http://localhost:8000](http://localhost:8000)
- **🐘 PgAdmin (управление БД):** [http://localhost:5050](http://localhost:5050)
  - **Email:** `admin@example.com`
  - **Пароль:** `admin`

## 📊 Описание отчетов

На странице `http://localhost:8000` доступны два ключевых показателя за выбранный период:

1.  **Выручка врача:** Сумма успешных транзакций (`patients_transaction`), привязанных к этапам лечения (`appointments_treatmentplanstage`) и приемам (`appointments_appointment`) конкретного врача. Учитываются только не отмененные операции.
2.  **Перенаправляемость (Referral Rate):** Процент пациентов, которые после первичного приема у данного врача обращались к другим специалистам клиники. Рассчитывается на основе временных меток приемов.

## 🔒 Безопасность и архитектура

-   **Read-Only доступ:** Подключение приложения к базе данных настроено в режиме "только чтение" на уровне драйвера SQLAlchemy и прав пользователя PostgreSQL. Изменение данных через интерфейс невозможно.
-   **Изоляция данных:** База данных разворачивается локально внутри Docker-контейнера из предоставленного дампа. Данные не покидают ваше окружение.
-   **Адаптивность:** SQL-запросы адаптированы под специфическую схему Django-проекта Cliniciq2 (связи через `treatment_stage_id` и `appointment_id`).

## ❓ Решение проблем

### Ошибка "Connection refused" или пустая страница
1.  Убедитесь, что Docker запущен.
2.  Проверьте логи приложения: `docker compose logs app`.
3.  Убедитесь, что файл дампа `dump/cliniciq2_db.dump` существует и весит корректно (около 100+ МБ).
4.  Попробуйте очистить кэш браузера (`Ctrl+F5`) или открыть страницу в режиме Инкогнито.

### Ошибка "Large files detected" при git push
Файлы дампов (>100 МБ) нельзя хранить в Git напрямую. Если вы форкаете этот репозиторий:
1.  Удалите файл дампа из отслеживания: `git rm --cached dump/*.dump`.
2.  Добавьте `dump/*.dump` в `.gitignore`.
3.  Передавайте файл дампа заказчику отдельным архивом (ZIP/TAR) через облачное хранилище.
